# Project: NOAA Route, offline boat route planning for Android (plus Termux proof-of-concept scripts)

The main product is the NOAA Route Android app (`android/`): depth-aware route planning on NOAA ENC data, fully offline, GPX to OsmAnd+, plus NOAA chart maps converted for OsmAnd. The Termux scripts (`noaa-route.py`, `noaa-charts.sh`, `noaa-ecdis-tiles.sh`) are the proof of concept the app grew from and are kept as the reference implementation. Owner: Jason, Chesapeake Bay boater (home waters: Middle River, MD; keeps the boat at Maryland Marina, 39.32371,-76.39998). Boat: **1.8 ft draft, uses 3 ft safe operating depth (`-d 3`), 10 ft air draft**. Read `README.md` for user-facing usage.

## Files
- `noaa-charts.sh`: downloads NOAA NCDS regional MBTiles (paper-chart style, depths in feet) from `https://distribution.charts.noaa.gov/ncds/mbtiles/ncds_XX.mbtiles` and converts to OsmAnd `.sqlitedb`. `-M` merges multiple regions into one `ncds_XX_YY.sqlitedb` (`-S` = separate; asks if neither). **Working and confirmed on device.**
- `noaa-ecdis-tiles.sh`: pulls 256px tiles for a bbox from NOAA's ECDIS Display Service (S-52 style, depths in meters) via the ArcGIS MCS `export` endpoint and packs them into `.sqlitedb`. Auto-refresh/resume logic. **Confirmed on device.**
- `noaa-route.py`: route planner. NOAA ENC S-57 (state zip, updates applied by GDAL `UPDATES=APPLY`) -> per-cell GeoPackage cache -> rasterized Byte grid (gdal_rasterize, bands burned low to high detail, each cell resets its own M_COVR coverage) -> numpy grid preparation (`prepare()`, needs `pkg install python-numpy`) -> Python A* -> GPX `<rte>`. Same planning structure as the app (`plan()` / `plan_piece()` / `guide_points()`). Python because routing in bash is impractical. **Confirmed on device:** Middle River to Annapolis (3 ft draft, 26.3 nm) and Maryland Marina to Chesapeake City public dock (34.3 nm, via APG waters and C&D Canal) import and display correctly in OsmAnd (2026-10-11).
- `android/`: NOAA Route app, Kotlin, no AndroidX. Core (`MiniJson`, `Pack`, `ChartSet`, `Planner`, `Gpx`, `Coords`, `Shared`, `Regions`) is Android-free so it compiles and tests on a plain JVM (`kotlinc` + junit jars, see below). Tests: `PlannerTest` (synthetic packs incl. joining two areas), `SharedTest` (share text/GPX parsing), `RegionsTest` (NCDS table, catalog, trip needs, Chesapeake swap), `AreaRoutesTest` (reference routes, only with PACK_DIR/AREAS_JSON). `MainActivity` is programmatic UI; `RegionMapView` (region map), `PackStore` (catalog, downloads, auto setting) and `UpdateJob` (daily Wi-Fi updates) are the Android side of regions. minSdk 29, largeHeap.
- `tools/build_route_pack.py` + `tools/areas.json`: builds NRPK2 area packs (format in the docstring) with python3-gdal + numpy on a **global grid** (dlat = 20 m, dlon = 20 m at 38 N, tiles numbered from 90 N/180 W) so areas join in the app (`ChartSet`). Checks DSPM_DUNI == 1 (meters) per cell, records DSPM_SDAT (12 = MLLW). Weekly `route-pack.yml` builds all areas, runs `AreaRoutesTest` (reference routes from areas.json via the Kotlin planner, env PACK_DIR/AREAS_JSON) and only then publishes `packs/*.bin` + `catalog.json` to release `route-pack` (main) or the `route-pack-beta` pre-release (branch runs; APKs built from a branch read it via BuildConfig.PACK_BASE). Areas: NCDS regions `ncds_02a`, `ncds_02b`, `ncds_03`, `ncds_04`, `ncds_05`, `ncds_06`, `ncds_07`, `ncds_08`, `ncds_10`, `ncds_11`, `ncds_15` (cells from NOAA's ENC catalog by coverage; 1.7-6.7 MB each, build ~25 min for all eleven). The old `chesapeake` area (MD+VA+DE state sets) was removed from areas.json and the release on 2026-10-14; the app still swaps an installed copy for 04+05 via `Regions.RETIRED` (the builder's state-set path still works for legacy areas). The first single-pack build (NRPK1, `md-route-pack.bin`, 3.1 MB) is obsolete; the app deletes it.
- `.github/workflows/android.yml`: unit tests + signed release APK on pushes to `android/`, published as release `app` (`noaa-route.apk`). Signing key: secrets `NOAAROUTE_KEYSTORE_B64`, `NOAAROUTE_KEYSTORE_PASSWORD`, `NOAAROUTE_KEY_ALIAS`, `NOAAROUTE_KEY_PASSWORD`; local copy in `~/.noaa-route-signing/` (never commit it).
- `README.md`: user guide. Leads with the app (install, quick start, features, regions, chart maps, planner rules); the scripts are a later "Proof of concept" section. Keep that focus, and keep it in sync with app and script changes.

## Hard-won technical decisions (do not regress)
- **OsmAnd `.sqlitedb` format must match tarwirdur/mbtiles2osmand exactly:**
  - `CREATE TABLE tiles (x int, y int, z int, s int, image blob, PRIMARY KEY (x,y,z,s));`
  - `CREATE TABLE info (maxzoom Int, minzoom Int);` with values `max(z), min(z)` of stored z
  - `y = 2^zoom - 1 - tile_row` (MBTiles TMS to XYZ); `z = 17 - zoom` (BigPlanet inverted zoom)
  - An earlier version added `inversiveZoom`, `tilesize`, `ellipsoid`, `timecolumn`, `url` columns to `info`: **OsmAnd displayed nothing.** Do not add extra columns.
- **Termux storage race:** `termux-setup-storage` returns before the user answers and then rebuilds `~/storage`. Scripts wait for the `~/storage/downloads` symlink before creating folders. Keep this.
- **OsmAnd imports a copy.** Editing a file in Download does not change what OsmAnd shows; the user must delete the old map in Maps & Resources > Local and re-import.
- **ECDIS refresh safety:** a refresh that ends with failed tiles must never overwrite an existing complete `.sqlitedb`. The `.refreshing` marker in the tile cache tracks an unfinished refresh.
- Shebang is `#!/data/data/com.termux/files/usr/bin/bash` (Termux path).
- Scripts use `set -euo pipefail`; watch for `grep` with no matches killing pipelines.
- **Merge:** per-region `.sqlitedb` files are kept as merge sources. Overlapping tiles keep the larger image via `INSERT ... ON CONFLICT DO UPDATE` (needs SQLite 3.24+). Merged map is rebuilt only if a region changed, `-f`, or it is missing.

- **Route planner rules:** US ENC depth areas step 0/1.8/3.6 m, so a 3 ft draft falls inside the 0-1.8 m band. That band is "marginal" (cost x4, flagged), not blocked, with soundings < draft as hazards. Bridges: decks without VERCLR block, spans with VERCLR re-open (most detailed cell wins, same reset as depths); without this the route went under the Bay Bridge's low Sandy Point approach spans. Restricted areas: only navigation RESTRN codes are flagged; Maryland's bay-wide no-discharge zone (RESTRN 16) otherwise drowns them out.
- `noaa-route.py -l` starts from `termux-location` (GPS 90 s, then network 30 s). Needs Termux:API app + `pkg termux-api` + Location permission; verified a fix is returned (from inland, so no full route from a live fix yet).
- Route planner lessons from Hart-Miller to Bear Creek (2026-10-11): (1) search box padding must be generous (now max(0.06 deg, 25% of span), auto-widened x2.5 then x5 on failure); Sparrows Point sat on the old box edge. (2) Opening bridges (CATBRG 2,3,4,5,7,8) have no VERCLR and were walls; now passable and reported. (3) PILPNT/PYLONS are visible structures: blocked cell only, no hazard buffer (the 60 m buffer closed the swing span). (4) SPAN_OK is dilated 1 cell so an opening cuts the all-touched deck band. (5) Auto resolution 10-60 m, finest under 5M cells. (6) M_COVR reset now clears all 5 flag bands, otherwise overview cells' whole-bridge polygons (US3 "Eastern Channel Bridge", 58 ft) leaked into reports.
- Route planner speed/debug (2026-10-11): rasterizing per cell (~20 gdal calls per cell, ~60 ms process overhead each) took ~55 s for 45 cells; now one OGR VRT union layer per usage band (`band{N}.vrt`), ~9 s. On failure, `enclosure()` checks whether each end's water reaches the grid edge; if not, it stops (no wasted widening, which cost ~4 min) and lists the walls. DEPARE too shallow is burned as SHALLOW (5) so diagnostics can tell it from land.
- Overhead cables (2026-10-16, branch cable-vercsa): some power cables carry only VERCSA (safe vertical clearance), no VERCLR. As unknown clearance they were walls: two by the Amtrak swing bridge over the Bush River sealed off the upper river (Gabler's Shore, 39.44288,-76.23491; "pocket of 602 ha", and the "try 2.5 ft" hint was misleading). Builder and noaa-route.py now use VERCSA when VERCLR is missing (10 of 1,586 cables in the MD/VA/DE/NC cache). Reference route "Maryland Marina to upper Bush River". When a "pocket" explanation lists a bridge or cable, check the CBLOHD attributes first.
- Single PILPNT/PYLONS points no longer block (one pile closed Ego Alley at 20 m grid); only area geometries do (`OGR_GEOMETRY IN ('POLYGON','MULTIPOLYGON')`).
- `-d` is the safe operating depth, not boat draft (Jason: 1.8 ft draft, 3 ft safe depth). Depths compared with ROUNDING_M = 0.05 since NOAA stores 6 ft as 1.8 m.

- Shore clearance (2026-10-14): (1) shore proximity reach is SHORE_M = 100 m in cells, min 5 (K was a fixed 5 cells, only 40 m on the 10 m grid), cost 1 + 2.4/(K-1) per level (identical at K=5). (2) Proximity distance alternates 8- and 4-neighbor steps (octagonal); 4-neighbor only made water diagonal off a headland look 1.4x farther. (3) simplify's +1 staircase tolerance no longer applies in the two rings nearest danger. (4) line_cells/lineCells report diagonal-step corner cells, which must be usable water (a leg slipped between the two cells of a diagonal pier line). (5) An end moved to water (snap or cut-off) keeps that water as its own waypoint; the leg to the user's point is flagged "connects your point to usable water". (6) SLCONS (piers, seawalls, jetties: about 1,500 lines in the MD band 5 cells) were not in LAYERS at all. As hard walls they sealed Bear Creek's bascule span (fender lines) and Rock Hall's inner harbor, so they are passable at PIER_COST = 50, count as danger for proximity, cost a diagonal slip past a pier corner like entering it (A*), and simplify may not cross more pier steps than the path. noaa-route.py: flag band 6. Packs: HAZARD plane value 255 (HZ_PIER), which apps before this read as a 25.4 m obstruction (no effect), so no format change. Tried and rejected: LNDARE all touched (closed Rock Hall's entrance at 20 m).
- OGR_GEOMETRY where clauses match nothing on the GeoPackage cache (noaa-route.py's PILPNT/PYLONS area filter has never matched: piers drawn as areas are not blocked in the script; the pack builder checks geometry in Python and is fine). Do not filter by geometry type in gdal_rasterize -where.
- gpkg cache layer list is now `<cell>.gpkg.layers2` ({"layers": LAYERS, "have": ...}) so adding a layer rebuilds the cache; the old `.layers` (plain list) is left for older script copies.

- Long-trip ends (2026-10-15, branch channel-marks; Maryland Marina to Carolina Beach at 5 ft): (1) Guide points are refined to channel water (nearest SAFE, usable, non-pier cell within max(overview res, 300 m)). (2) Each end is worked out at 20 m within APPROACH_M = 20 km (snap, cut-off escape, then a full cost field = Dijkstra with astar's moves and costs, indexed heap). The overview A* (astarEnds / astar_ends) may only start or finish on an overview cell wholly inside an end's window, at the cheapest 20 m cost in it, and never crosses a window on its own cells; guide points follow the traced 20 m path every 8 km (FINE_GUIDE_M; a stretch window reaches 6.7 km past its points). Ends in each other's windows can also meet directly in 20 m water. Tried and rejected: stamping 40 m detail into the overview (center sampling dropped the 1-cell ICW channel and opened Carolina Beach Inlet), stamping 20 m reachability (an ocean cell reachable via Masonboro sat next to a sound cell reachable down the ICW: the overview walked across Pleasure Island, and the last stretch then failed at 20 m and widened to 40 m into the sound). (3) Carolina Beach Inlet at 5 ft is a one-cell gap between shoal-sounding buffers: noaa-route.py puts all of a long trip's 20 m grids on the end window's lattice (Grid align), otherwise it was open in one grid and shut in the next. (4) Packs share one 160-tile decompressed cache (Pack.tileCache, about 63 MB); 160 tiles per pack ran the reference test out of memory with six packs. (5) Pack builder burns depth areas shallow to deep with DRGARE after DEPARE (deeper wins), like noaa-route.py. (6) Route test workflow prints the log tail when tests die without a failure report. Python long trips now take 5-15 min on the phone (cost fields are pure Python).

## Vector ENC charts for OsmAnd (issue #2, in the app since 2026-10-16)
First attempt (abandoned): raw ENC S-57 to OSM with JOSM SeaChart `js57toosm`, then OsmAndMapCreator on the phone (needed an Android-native sqlite-jdbc swap). `js57toosm` ignores ENC update files (.001+), so the data lacked Notice to Mariners corrections; dropped in favor of ECDIS tiles.

Released 2026-10-16 (branch vector-maps, merged): `vector-maps.yml` builds every NCDS region in areas.json each Saturday (15:00 UTC, after route packs) and publishes `Ncds_XX_depth.depth.obf` + `Ncds_XX_seamarks.obf` + catalog.json (version 1: regions[ncds, name, created, cells, files[kind, file, size, sha256]]) to release `vector-maps` (main) or `vector-maps-beta` (branch runs; branch APKs read it via BuildConfig.VECTOR_BASE). The catalog is merged with the published one, so a partial run keeps other regions; regions that fail are left out. Push = quick check only (Middle River box + 04, strict tags); a commit message with `[vector all]` or `[vector 26b 07]` builds and publishes those regions from a branch (workflow_dispatch needs the file on main). All 46 regions: 620 MB, 0.3 MB (19d) to 27 MB (22a), most jobs a few minutes. 26b (Aleutians, at 180) loses ~2% of coastal soundings in OsmAnd; tools/osm_to_obf.sh fails a sounding section only below 97%. App: VectorMaps.kt (state in prefs "vector", DownloadManager into app storage, SHA-256 check and copy to Download/noaa-charts in ChartJob via DownloadFiles), region card section "Vector charts for OsmAnd". **Open in OsmAnd (ACTION_VIEW, MediaStore content URI, application/octet-stream, setPackage) imports .obf files: confirmed on device 2026-10-16.** Chart/vector notices open the region card (MainActivity.EXTRA_REGION); they had no tap action before.

Proof of concept 2026-10-16 with GDAL (updates applied) for Middle River and Back River (findings in the issue #2 comment): `tools/enc_to_osm.py` (ENC to OSM seamark/depth tags, most detailed chart per object, areas merged across cells), `tools/obf_compare.py` (tags written vs kept, from BinaryInspector's `types [k-v] add_types [...] Names [k(n) - v]` lines), `.github/workflows/enc-vector-poc.yml`. Lessons:
- Released OsmAnd's depth rules (depthcontourlines.addon, 2023) draw only `contourtype` 5m/10m/20m/50m/100m/200m/1000m; `2m`, `minor` and `contourarea=depth` shading came to OsmAnd's development version in September 2026. NOAA's shallow contours are written as `5m` class; the `name` tag carries the depth.
- Jason's map style is **Nautical** (not Marine); its default contour colors (white, red) are about 27% opaque, dark brown is the most visible.
- OsmAnd prints every text tag: one label per object, in whole feet (NOAA stores feet rounded to 0.1 m).
- No dredged area type in OsmAnd: DRGARE is written as `seamark:type=fairway` named "<section>, dredged N ft" (draws as a green band). Seabed areas are outlined, so same-tag areas are merged across chart cells (cell edges showed as straight lines).
- `.depth.obf` files go to OsmAnd's nautical folder (loaded with the free Nautical plugin); the file type was not the problem. OsmAnd's own depth maps (e.g. Swiss_Lakes_contours_2) use the same contour tags and no depth areas.
- Region builds (2026-10-16): `enc_to_osm.py -r 04` (region box from build_route_pack.region_bbox) or `-b W,S,E,N`. Coverage per cell = its panel polygons in ENCProdCat.xml in a 0.25 degree grid (an object is cut only against more detailed cells meeting it); OSM written streaming (nodes/ways/relations to temp files). Region 04: 250 cells converted in 26 s, whole CI job ~5 min; maps 13 MB depth + 8.8 MB seamarks (NCDS raster ~600 MB).
- Two maps per area, like OsmAnd's own depth maps (OsmAnd-tools obf-generation/contours/V4/depth/build_depth_region.sh): `<Name>_depth.depth.obf` (Nautical maps, follows the Nautical depth switch) = contours/depth areas (`generate-map`, default zooms) merged with `merge-index` with three sounding sections (`generate-map --map-zooms=11-12`, `13-14`, `15-`: soundings from the most detailed chart up to band 3, band 4, any band). `<Name>_seamarks.obf` (`generate-obf-no-address`) goes to Standard maps, which is right (OsmAnd's own seamarks come from standard maps) and lets Jason deactivate it alone.
- **OsmAnd drops a trailing `_<number>` from map display names as a version** (Algorithms.java): `Depth_ncds_04.depth.obf` showed as "Depth ncds". Names must not end in digits: `Ncds_04_depth`, `Ncds_04_seamarks`.
- BinaryInspector `-vmapobjects` lists only objects visible at `-zoom=` (default 15): low-zoom sections show "Total map objects: 0" though they hold data. The workflow dumps zoom 11 and 13 too and checks each sounding section's count; `obf_compare.py --require` fails the build if an essential tag is not written or not kept.
- CI caches enc-work (cells + catalog) per matrix entry and OsmAndMapCreator per ISO week (actions/cache). Matrix: `Test_middle_river` box + `Ncds_<region>` (workflow_dispatch input `region`, default 04).
- Pink diagonal hatching over Aberdeen Proving Ground waters is OsmAnd's base map (OSM landuse=military / military=danger_area), not ours: Marine/Nautical style hatch restricted_area only with `category=military`; our APG area (RESTRN 8, entry restricted) draws faint yellow with a red outline. Those waters are a danger zone closed only during firing (33 CFR 334.140); the planner only flags restricted areas.
- Open: OpenStreetMap seamarks show twice (OsmAnd's map and ours), daymarks and light sectors not mapped, one contour style.
