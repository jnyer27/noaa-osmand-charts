# Project: NOAA Route, offline boat route planning for Android (plus Termux proof-of-concept scripts)

The main product is the NOAA Route Android app (`android/`): depth-aware route planning on NOAA ENC data, fully offline, GPX to OsmAnd+, plus NOAA chart maps converted for OsmAnd. The Termux scripts (`noaa-route.py`, `noaa-charts.sh`, `noaa-ecdis-tiles.sh`) are the proof of concept the app grew from and are kept as the reference implementation. Owner: Jason, Chesapeake Bay boater (home waters: Middle River, MD; keeps the boat at Maryland Marina, 39.32371,-76.39998). Boat: **1.8 ft draft, uses 3 ft safe operating depth (`-d 3`), 10 ft air draft**. Read `README.md` for user-facing usage.

## Files
- `noaa-charts.sh`: downloads NOAA NCDS regional MBTiles (paper-chart style, depths in feet) from `https://distribution.charts.noaa.gov/ncds/mbtiles/ncds_XX.mbtiles` and converts to OsmAnd `.sqlitedb`. `-M` merges multiple regions into one `ncds_XX_YY.sqlitedb` (`-S` = separate; asks if neither). **Working and confirmed on device.**
- `noaa-ecdis-tiles.sh`: pulls 256px tiles for a bbox from NOAA's ECDIS Display Service (S-52 style, depths in meters) via the ArcGIS MCS `export` endpoint and packs them into `.sqlitedb`. Auto-refresh/resume logic. **Confirmed on device.**
- `noaa-route.py`: route planner. NOAA ENC S-57 (state zip, updates applied by GDAL `UPDATES=APPLY`) -> per-cell GeoPackage cache -> rasterized Byte grid (gdal_rasterize, bands burned low to high detail, each cell resets its own M_COVR coverage) -> numpy grid preparation (`prepare()`, needs `pkg install python-numpy`) -> Python A* -> GPX `<rte>`. Same planning structure as the app (`plan()` / `plan_piece()` / `guide_points()`). Python because routing in bash is impractical. **Confirmed on device:** Middle River to Annapolis (3 ft draft, 26.3 nm) and Maryland Marina to Chesapeake City public dock (34.3 nm, via APG waters and C&D Canal) import and display correctly in OsmAnd (2026-10-11).
- `android/`: NOAA Route app, Kotlin, no AndroidX. Core (`MiniJson`, `Pack`, `ChartSet`, `Planner`, `Gpx`, `Coords`, `Shared`, `Regions`) is Android-free so it compiles and tests on a plain JVM (`kotlinc` + junit jars, see below). Tests: `PlannerTest` (synthetic packs incl. joining two areas), `SharedTest` (share text/GPX parsing, Google Maps links), `GpxTest` (check markers, note wording; writes `app/build/gpx-sample.gpx`, which android.yml validates with xmllint against `app/src/test/resources/gpx.xsd`), `RegionsTest` (NCDS table, catalog, trip needs, Chesapeake swap), `AreaRoutesTest` (reference routes, only with PACK_DIR/AREAS_JSON). `MainActivity` is programmatic UI; `RegionMapView` (region map), `PackStore` (catalog, downloads, auto setting) and `UpdateJob` (daily Wi-Fi updates) are the Android side of regions. minSdk 29, largeHeap.
- `tools/build_route_pack.py` + `tools/areas.json`: builds NRPK2 area packs (format in the docstring) with python3-gdal + numpy on a **global grid** (dlat = 20 m, dlon = 20 m at 38 N, tiles numbered from 90 N/180 W) so areas join in the app (`ChartSet`). Checks DSPM_DUNI == 1 (meters) per cell, records DSPM_SDAT (12 = MLLW). Weekly `route-pack.yml` builds all areas, runs `AreaRoutesTest` (reference routes from areas.json via the Kotlin planner, env PACK_DIR/AREAS_JSON) and only then publishes `packs/*.bin` + `catalog.json` to release `route-pack` (main) or the `route-pack-beta` pre-release (branch runs; APKs built from a branch read it via BuildConfig.PACK_BASE). Areas: NCDS regions `ncds_02a`, `ncds_02b`, `ncds_03`, `ncds_04`, `ncds_05`, `ncds_06`, `ncds_07`, `ncds_08`, `ncds_10`, `ncds_11`, `ncds_15` (cells from NOAA's ENC catalog by coverage; 1.7-6.7 MB each, build ~25 min for all eleven). The old `chesapeake` area (MD+VA+DE state sets) was removed from areas.json and the release on 2026-10-14; the app still swaps an installed copy for 04+05 via `Regions.RETIRED` (the builder's state-set path still works for legacy areas). The first single-pack build (NRPK1, `md-route-pack.bin`, 3.1 MB) is obsolete; the app deletes it.
- `.github/workflows/android.yml`: unit tests + signed release APK on pushes to `android/`, published as release `app` (`noaa-route.apk`). Signing key: secrets `NOAAROUTE_KEYSTORE_B64`, `NOAAROUTE_KEYSTORE_PASSWORD`, `NOAAROUTE_KEY_ALIAS`, `NOAAROUTE_KEY_PASSWORD`; local copy in `~/.noaa-route-signing/` (never commit it).
- `tools/build_osf.py`: the vector charts as an OsmAnd custom plugin (`noaa-charts.osf`, pluginId `noaa.charts`), written by vector-maps.yml's publish job with `Ncds_XX_depth_2.depth.obf.zip` / `Ncds_XX_seamarks_2.obf.zip` (OsmAnd downloads only zipped maps and strips the `_2` version on install, so they install as the app's names) and `osmand-items.json`. Each region's download group loads its items from that file (`items-url`, OsmAnd CustomRegion.DynamicDownloadItems) so weekly builds reach OsmAnd without reinstalling; `--static` embeds them instead. The catalog's file entries gain `osmand_zip`/`osmand_zip_size` (the app ignores them). **Confirmed on device 2026-10-20** (beta build 7, region 04: plugin installs, the region list loads from osmand-items.json, maps download).

## Hard-won technical decisions (do not regress)
- **OsmAnd `.sqlitedb` format must match tarwirdur/mbtiles2osmand exactly:**
  - `CREATE TABLE tiles (x int, y int, z int, s int, image blob, PRIMARY KEY (x,y,z,s));`
  - `CREATE TABLE info (maxzoom Int, minzoom Int);` with values `max(z), min(z)` of stored z
  - `y = 2^zoom - 1 - tile_row` (MBTiles TMS to XYZ); `z = 17 - zoom` (BigPlanet inverted zoom)
  - An earlier version added `inversiveZoom`, `tilesize`, `ellipsoid`, `timecolumn`, `url` columns to `info`: **OsmAnd displayed nothing.** Do not add extra columns.
- **Termux storage race:** `termux-setup-storage` returns before the user answers and then rebuilds `~/storage`. Scripts wait for the `~/storage/downloads` symlink before creating folders. Keep this.
- **OsmAnd imports a copy.** Editing a file in Download does not change what OsmAnd shows; the user must delete the old map in Maps & Resources > Local and re-import.
- **ECDIS refresh safety:** a refresh that ends with failed tiles must never overwrite an existing complete `.sqlitedb`. The `.refreshing` marker in the tile cache tracks an unfinished refresh.
- Shebang is `#!/data/data/com.termux/files/usr/bin/bash` (Termux path).
- Scripts use `set -euo pipefail`; watch for `grep` with no matches killing pipelines.
- **Merge:** per-region `.sqlitedb` files are kept as merge sources. Overlapping tiles keep the larger image via `INSERT ... ON CONFLICT DO UPDATE` (needs SQLite 3.24+). Merged map is rebuilt only if a region changed, `-f`, or it is missing.

- **Route planner rules:** US ENC depth areas step 0/1.8/3.6 m, so a 3 ft draft falls inside the 0-1.8 m band. That band is "marginal" (cost x4, flagged), not blocked, with soundings < draft as hazards. Bridges: decks without VERCLR block, spans with VERCLR re-open (most detailed cell wins, same reset as depths); without this the route went under the Bay Bridge's low Sandy Point approach spans. Restricted areas: only navigation RESTRN codes are flagged; Maryland's bay-wide no-discharge zone (RESTRN 16) otherwise drowns them out.
- `noaa-route.py -l` starts from `termux-location` (GPS 90 s, then network 30 s). Needs Termux:API app + `pkg termux-api` + Location permission; verified a fix is returned (from inland, so no full route from a live fix yet).
- Route planner lessons from Hart-Miller to Bear Creek (2026-10-11): (1) search box padding must be generous (now max(0.06 deg, 25% of span), auto-widened x2.5 then x5 on failure); Sparrows Point sat on the old box edge. (2) Opening bridges (CATBRG 2,3,4,5,7,8) have no VERCLR and were walls; now passable and reported. (3) PILPNT/PYLONS are visible structures: blocked cell only, no hazard buffer (the 60 m buffer closed the swing span). (4) SPAN_OK is dilated 1 cell so an opening cuts the all-touched deck band. (5) Auto resolution 10-60 m, finest under 5M cells. (6) M_COVR reset now clears all 5 flag bands, otherwise overview cells' whole-bridge polygons (US3 "Eastern Channel Bridge", 58 ft) leaked into reports.
- Route planner speed/debug (2026-10-11): rasterizing per cell (~20 gdal calls per cell, ~60 ms process overhead each) took ~55 s for 45 cells; now one OGR VRT union layer per usage band (`band{N}.vrt`), ~9 s. On failure, `enclosure()` checks whether each end's water reaches the grid edge; if not, it stops (no wasted widening, which cost ~4 min) and lists the walls. DEPARE too shallow is burned as SHALLOW (5) so diagnostics can tell it from land.

## GPX check markers and OsmAnd (2026-10-18)
- Gpx.flagged(leg): shoalM > 0 or a note containing "check" (bridge, cable and restricted area notes are information only). Runs of consecutive flagged legs get a start marker "Check: legs a-b (x.xx nm)" with every note, and an end marker "Check ends: legs a-b". Flagged rtepts are renamed "WPnn check" with cmt, sym and type. Element order in wpt follows the GPX 1.1 schema (name, cmt, desc, sym, type, extensions).
- OsmAnd: namespace `xmlns:osmand="https://osmand.net"`; icon names come from OsmAnd-resources `poi/poi_categories.json` (`special_symbol_exclamation_mark`, `special_symbol_check_mark`); `osmand:background` triangle/circle, `osmand:color` #AARRGGBB. `<type>` becomes the waypoint group. OsmAnd ignores `<sym>` for its icons.
- OsmAnd announces GPX waypoints (WaypointHelper.java) only in following mode, with `SHOW_WPT` (global, "Show along the route: GPX waypoints") and `ANNOUNCE_WPT` (per profile, voice prompts) on, within 500 m of the route, timed by speed and distance; the group does not matter. Jason's first test at the dock did not announce (not moving); simulate navigation to test.
- Shallow notes: "N m where charted depth may be under D ft" (MARGINAL = depth area range straddling the safe depth, so the 6-12 ft band for 8 ft; the old fixed "0-6 ft" label was wrong above 6 ft). shoalM = marginal half-cell samples along the leg's line x leg length / samples (fewer than 2 count as 0). The sounding is the shallowest within 100 m of the leg segment (a strip, not a circle), "under your D ft" when shallower.
- Hazard notes (Planner.nearestHazard): the closest HAZARD cell (sounding or obstruction under the safe depth; obstructions to depth + 1 ft) or snag within the buffer radius plus a cell, as "passes lo-hi m from a charted 3.2 ft sounding: check" (range = distance +- res/2, rounded out to 5 m). Packs merge OBSTRN/WRECKS/UWTROC, so all are "obstruction"; unknown depth is stored as 0 m. One note per hazard along a stretch; generic SOFT_NOTE if none found.

## Security zones (2026-10-19, packs only)
- NOAA charts many Coast Guard security zones (33 CFR 165) as RESARE with no RESTRN code, only "33 CFR 165.502" in INFORM (Cove Point LNG terminal: CATREA 1), so routes crossed them with no note. The builder now marks a RESARE whose INFORM cites a security zone section, or whose OBJNAM says "Security Zone" when it has no code and no section, as RESNOTE with rule "security zone, entry may be prohibited: check": a check with GPX markers, never blocked. Jason chose this over blocking: he does not want to maintain a list of zones.
- Sections: tools/security_zones.py reads 33 CFR 165 from eCFR (versioner API needs Accept-Encoding gzip) and keeps sections whose text says a security zone is established (118 in the 2026-10-14 issue; 165.504 Newport News has no "Security Zone" in its heading). build_route_pack.py fetches them at start (load_security_zones), falls back to tools/security_zones.json, and logs new or removed sections and every zone found ("Security zone 33 CFR ... reported as a check").

## Try to avoid checks (2026-10-19)
- Planner.resolveChecks(route, pts): for each Gpx.checkRuns run (last first), skips OFF_WATER legs at its ends, pads up to 500 m of unflagged legs on each side (never past a user point), rebuilds the area grid and replans with strictGrid: soft (hazard buffer), pier, security zone cells (securityCells: RESNOTE cells near notes whose rules start with "security zone") and, on the first try, MARGINAL cells become walls; the stretch's ends stay open. Kept when no leg is flagged (first try) or, with MARGINAL allowed, no "check" note and shoalM no more than before + 1 m; and only if no longer than old + max(0.2 nm, 10%) (RESOLVE_EXTRA_M, RESOLVE_EXTRA_FRAC). Result route is name_adjusted with a Resolution summary.
- App: "Try to avoid checks" button, shown when the route has check runs; saves <name>_adjusted.gpx and switches route, report and GPX to it. Not a setting, by design: the user sees the plain route first.
- Reference routes: `"resolve": true` (run it) or a number (minimum stretches resolved) in areas.json; prints RESOLVE lines and POINTS (adjusted). First run (2026-10-19): Ego Alley 1 of 3 (-0.01 nm), Solomons to Stingray 1 of 2 (+0.35), Mobjack 5 of 5 (+0.02), Cove Point security zone 1 of 1 (+0.03), each under 0.5 s.
- Tried and rejected (2026-10-19): a least-exposure try for stretches with no way around (A* with cost growing toward each hazard, kept when the exposure halved). It moved 2 of 24 stretches on Maryland Marina to Carolina Beach and Jason saw no improvement in the ICW, where the checks are piles inside the channel or soundings at its edge. He chose the first version and not to work on ICW checks.

## Sharing from Google Maps (2026-10-18, 0.1.107)
- Google's Share sends "Name\nhttps://maps.app.goo.gl/..." with no coordinates. MainActivity.sharedText follows redirects (HttpURLConnection, no auto-follow, 8 s, max 6 hops, https Google hosts only, consent.google.com continue= taken as is) via Shared.resolveShort (pure, tested with a fake chain), then parses the long link. `!3d..!4d..` (the place) wins over `@` (map center); `/maps/search/lat,+lon` and `q=lat,+lon` read. Name-only links (`?q=Name&ftid=...`) get a dialog suggesting a dropped pin. Jason confirmed on the phone. osm2gmaps (F-Droid) is the guide's fallback for other map apps.
